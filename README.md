# ContactBench

A reproducible benchmark that tests AI models on the word game **Contact**, implementing protocol
**contact-v0.4** from [`CONTACT_BENCHMARK_SPEC.md`](CONTACT_BENCHMARK_SPEC.md), extended in **contact-v0.5** with
two dictionary conditions for large lexicons. In *closed-book* play, players are told only the dictionary's
identity. In *dictionary-assisted* play, every player may call the same deterministic lookup functions
`is_legal_word`, `list_words` and `count_words`. See [docs/decision_log.md](docs/decision_log.md).

Two cooperating guessers (separate model instances) try to reach a secret word known to a defender. Guesser 1
gives a public clue and privately registers an intended word. Guesser 2 privately registers a word. The defender
publishes a blocklist of any size. Registered words are then opened only as the reveal rules allow. A public utterance
of the secret wins, and a successful contact that earns the final letter also wins. All grading is done by ordinary
code: there is no LLM judge.

> **Status:** the implementation is complete and offline-verified. No paid model call has been made yet. The provider
> adapters were tested against mocked SDK clients only, and the first live smoke test is the researcher's step (see
> [Live runs](#live-runs)). All bundled results are synthetic fixture data.

## Setup

Requires Python 3.11–3.13.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock && .venv/bin/pip install -e . --no-deps
.venv/bin/python -m pytest            # 150+ offline tests, no keys, no network
```

## Commands

```text
contact-bench validate CONFIG [--live]          # offline preflight (lexicon, schemas, blocklist/context capacity)
contact-bench plan CONFIG                        # games, max decisions, optional cost upper bound
contact-bench demo --offline [--out DIR]         # end-to-end demo: fixture walkthrough → run → replay → analysis → export → site
contact-bench run CONFIG --offline               # scripted + fake-adapter tournaments only
contact-bench run CONFIG --live --max-requests N [--max-usd X]
contact-bench smoke CONFIG --provider {openai,anthropic,google} --live --max-requests N
contact-bench resume RUN_ID (--offline | --live --max-requests N)
contact-bench replay RUN_ID                      # regenerate every game from the decision log; verify equivalence
contact-bench analyze RUN_ID [--bootstrap N]     # ratings, efficiency, bootstrap CIs, matrices, figures, report.md
contact-bench export RUN_ID --public [--include-audit] [--out DIR]
contact-bench build-site EXPORT_DIR [...] [--out site_build]
contact-bench show RUN_ID GAME_ID --view {public,guesser1,guesser2,defender,audit}
contact-bench audit RUN_ID [--model ID] [--rate R] [--max-items N]   # frozen clue bank + shadow forecast audit
contact-bench reference --hist 3:2,8:3 --C 8     # R_C(h, ell) for a length histogram
contact-bench build-lexicon SOURCE --name ... --license ... --source-description ... --source-revision ...
```

Run data is written to `runs/<RUN_ID>/` (change it with `--runs-dir`):

| File | Contents |
|---|---|
| `run.json` | Frozen configuration snapshot, protocol/engine/packing/RNG/prompt versions and hashes, code revision, lock hash, lexicon manifests |
| `private/tasks_private.jsonl` | Referee-only task manifest (secrets); never shown to players |
| `decisions.jsonl` | **Append-only source of truth.** One canonical decision per `run/game/turn/seat/phase` ID, plus its observation hash |
| `requests.jsonl` | Provider request records: usage, latency, attempts, errors (sanitized), cost estimates |
| `events.jsonl`, `index.sqlite` | Lifecycle events and a transactional status index |
| `games/*.json` | Derived game records (regenerated by `replay`) |
| `analysis/` | `analysis.json`, `leaderboard.csv`, `pairwise.csv`, `games.csv`, `report.md`, `figures/*.svg` |

## Repository layout

```text
contact_bench/
  engine/        pure game engine (admission, staged sealed round, reveal/cancel, final-letter contact)
  observations/  allowlist-built seat observations
  prompts/       versioned, hashed player prompts
  policies/      scripted baselines (Section 11) and the LLM seat agent
  providers/     OpenAI Responses, Anthropic Messages, Gemini Interactions (+ generateContent), offline fake
  runner/        tasks, balanced paired schedule, budgets, append-only store, resume, replay
  scoring/       character-packing reference R_C: exact shortcuts, exact rational oracle, length-class Monte Carlo
  analysis/      batch Elo-style rating, cluster bootstrap, efficiency/role statistics, SVG figures
  forecasts/     sparse forecasts, proper scores, frozen item bank, shadow audit
  export/        allowlist public exporter with credential scanning
  site/          static leaderboard builder (no backend, no CDN)
  cli/           contact-bench command
configs/         offline_example.yaml, baselines.yaml, live_example.yaml (placeholders rejected)
lexicons/        CC0 fixture lexicons with manifests and SHA-256
tests/           acceptance tests for spec Section 18, plus property tests
docs/            methodology, decision log, acceptance checklist, providers, website, reproducibility, licenses
```

## Live runs

1. Pick a production lexicon. Build it with `build-lexicon` from a source you are allowed to redistribute, or publish
   only the recipe and its hash.
2. Copy `configs/live_example.yaml`. Replace the placeholder model IDs with verified ones, set `max_output_tokens`,
   `context_window_tokens` and an optional dated `prices` table, then run `contact-bench validate CONFIG --live`.
3. Export `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GEMINI_API_KEY` (see `.env.example`). Credentials are read only
   from the environment and are never written to snapshots, logs or exports.
4. Run `contact-bench smoke CONFIG --provider P --live --max-requests 20` for each provider. Then resume that smoke
   run once to check recovery.
5. Freeze the decisions in spec Section 20 before a main run. These are listed in
   [`docs/decision_log.md`](docs/decision_log.md).

Paid execution always requires `--live` and an explicit request and/or dollar budget. Offline mode never falls back to
a provider.
